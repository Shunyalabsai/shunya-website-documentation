ASR configuration

Every parameter you can pass to POST /v1/audio/transcriptions, in one place. Only the audio source is required; everything else has a documented default. Authenticate with the access token from POST /auth/token — never your raw API key.

Audio source

Send exactly one of these three fields. The file size limit is 50 MB.

FieldTypeRequiredDescription
filefileone of file/audio_base64/urlAudio file (wav, mp3, flac, ogg/opus). Max 50 MB.
audio_base64string—Base64 audio instead of a file upload.
urlstring—URL to fetch the audio from.

Model

FieldTypeRequiredDescription
model string no ASR model — e.g. zero-indic, zero-universal, zero-med, zero-codeswitch. Defaults to the account model. Model guide →

Language

FieldTypeRequiredDescription
language_codestringnoLanguage (e.g. en, hi) or auto to detect. Default auto.

Diarization

FieldTypeRequiredDescription
diarizebooleannoReturn per-speaker segments. Default false.
num_speakersintegernoHint for the number of speakers (improves diarization).

Example: transcribe with per-speaker labels and a speaker count hint:

curl --location 'https://asrv2prod.shunyalabs.ai/v1/audio/transcriptions' \
  --header 'accept: application/json' \
  --header 'Authorization: Bearer <ACCESS_TOKEN>' \
  --form 'file=@"call.wav"' \
  --form 'language_code=hi' \
  --form 'diarize=true' \
  --form 'num_speakers=2'

With response_format=verbose_json, each segment carries a speaker label (SPEAKER_00, …), and the response includes speakers and speaker_turns.

Output format

FieldTypeRequiredDescription
response_formatstringnojson (default) or verbose_json.

json returns just the transcript:

{ "text": "the transcribed text" }

verbose_json adds timing, segments, words, and — when diarize=true — speakers:

{
  "text": "the transcribed text",
  "audio_duration": 8.0,
  "inference_time_ms": 116.6,
  "request_id": "c1a686efeedf",
  "success": true,
  "segments": [ { "start": 0.0, "end": 2.4, "text": "…", "speaker": "SPEAKER_00" } ],
  "words":    [ { "word": "…", "start": 0.0, "end": 0.3 } ],
  "speakers": [ "SPEAKER_00", "SPEAKER_01" ],
  "speaker_turns": [ { "start": 0.0, "end": 2.4, "speaker": "SPEAKER_00" } ]
}
NLP: intent, summary, sentiment
Transcript-level NLP (intent detection, summarization, sentiment analysis) is not a transcription flag — it runs on the separate POST /v1/speechintelligence endpoint with the text as input. Speech Intelligence →

Realtime streaming fields

The realtime endpoint (WS /v1/realtime) takes a different init set: token, required language (no auto-detect), sample_rate (default 16000, 8000 supported), diarize, and num_speakers. Streaming guide →

Putting it all together

curl --location 'https://asrv2prod.shunyalabs.ai/v1/audio/transcriptions' \
  --header 'accept: application/json' \
  --header 'Authorization: Bearer <ACCESS_TOKEN>' \
  --form 'file=@"call.wav"' \
  --form 'model=zero-indic' \
  --form 'language_code=hi' \
  --form 'diarize=true' \
  --form 'num_speakers=2' \
  --form 'response_format=verbose_json'

<ACCESS_TOKEN> is the short-lived token returned by POST /auth/token. Cache and reuse it until just before expires_at; re-mint on expiry or a 401.
