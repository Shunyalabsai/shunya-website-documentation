SIP / PSTN

For ASR streaming, send raw 16-bit signed PCM at 8 kHz or 16 kHz (sample_rate in the init message). On the TTS side, request raw PCM (response_format="pcm") on the OpenAI-compatible endpoint and let your telephony stack handle the final encoding.

ASR: accept telephony audio over WebSocket

The streaming endpoint accepts raw 16-bit signed PCM, little-endian, mono frames. For 8 kHz telephony audio, set sample_rate: 8000 in the init message (16 kHz is the default). Decode the G.711 stream from your SIP trunk to PCM before sending.

// First message after connecting to wss://asrv2prod.shunyalabs.ai/v1/realtime
{
  "token": "<access_token>",
  "language": "hi",
  "sample_rate": 8000
}
// then stream 16-bit signed PCM frames, and finish with the text message "end"

TTS: generate telephony-ready audio

Request raw PCM output on the OpenAI-compatible endpoint POST https://ttsv2.shunyalabs.ai/v1/audio/speech, then encode or forward the PCM bytes to your media pipeline.

from openai import OpenAI

token = "YOUR_TOKEN"   # short-lived Bearer token, see /api/auth/token
client = OpenAI(api_key=token, base_url="https://ttsv2.shunyalabs.ai/v1")

resp = client.audio.speech.create(
    model="tts-1",
    input="Hello, how are you today?",
    voice="Meera",
    response_format="pcm",
)
resp.stream_to_file("telephony.pcm")

Raw PCM output is useful for streaming and voice-agent pipelines. Select the response format required by your integration as supported by the API.

Why raw PCM matters here

ASR streaming consumes raw PCM (16-bit signed, mono) at 8 kHz or 16 kHz, so the G.711 codec used by your telephony trunk must be decoded to PCM before sending. On the TTS side, response_format="pcm" gives you the raw bytes to encode into whichever telephony format your IVR or SIP stack expects.

Pacing & finishing for telephony

The streaming init message has no latency knobs beyond token, language, sample_rate, diarize, and num_speakers. Latency is controlled by how you send frames and end the session:

  • Send 20–320 ms frames of raw 16-bit signed PCM, paced roughly in real time, so the server can emit partial transcripts while the caller is still speaking.
  • Finish with a text message end: the server finalises the session and returns the last final event.
  • For barge-in / interruption, treat an incoming partial/final event as the caller taking the floor and cancel any in-flight TTS playback. See LLM → TTS pipeline.

Source: Shunyalabs ASR Gateway API Reference (31 March), WebSocket Streaming API → "Audio Formats"; ShunyaLabs TTS API Integration Guide, §4 Voice Agent / OpenAI-Compatible TTS.
