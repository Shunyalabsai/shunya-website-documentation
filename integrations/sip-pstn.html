SIP / PSTN

For TTS output, Shunya Labs supports the two G.711 codecs that telephone networks use globally, mulaw and alaw. For ASR streaming, send raw 16-bit PCM at 8 kHz (sample_rate: 8000). Pick the codec that matches your geography or carrier.

Pick the codec

CodecWhen to useSample rate
mulaw (G.711 μ-law)Most Indian PSTN systems, North American telephony.8 kHz, 8-bit
alaw (G.711 A-law)European telephony systems and some SIP providers.8 kHz, 8-bit

ASR: accept telephony audio over WebSocket

The streaming endpoint accepts raw 16-bit signed PCM, little-endian, mono frames. For 8 kHz telephony audio, set sample_rate: 8000 in the init message (16 kHz is the default). Decode the G.711 stream from your SIP trunk to PCM before sending.

// First message after connecting to wss://asrv2prod.shunyalabs.ai/v1/realtime
{
  "token": "<access_token>",
  "language": "hi",
  "sample_rate": 8000
}
// then stream 16-bit signed PCM frames, and finish with the text message "end"

TTS: generate telephony-ready audio

Set response_format to the codec your trunk expects. The output is ready to forward to a SIP RTP stream or an IVR platform's audio sink.

# mulaw, North American / Indian PSTN
config = TTSConfig(model="zero-indic", voice="Varun", response_format="mulaw")
result = await client.tts.synthesize("<Conversational> Hello!", config=config)
# Forward result.audio_data directly to your media stream or IVR system

# alaw, European telephony
config = TTSConfig(model="zero-indic", voice="Rajesh", response_format="alaw")
result = await client.tts.synthesize("Guten Morgen!", config=config)

Why these codecs matter

ASR streaming consumes raw PCM (16-bit signed, mono) at 8 kHz or 16 kHz, so the G.711 codec used by your telephony trunk must be decoded to PCM before sending. On the TTS side, mulaw / alaw output at 8 kHz can be forwarded straight to a SIP RTP stream or an IVR platform's audio sink.

From the TTS docs:

mulaw (G.711 mu-law) and alaw (G.711 A-law) are the two standard codecs for telephone networks globally. Both encode audio at 8 kHz, 8-bit, which is the standard for PSTN, SIP, and most IVR platforms.

Pacing & finishing for telephony

The streaming init message has no latency knobs beyond token, language, sample_rate, diarize, and num_speakers. Latency is controlled by how you send frames and end the session:

  • Send 20–320 ms frames of raw 16-bit signed PCM, paced roughly in real time, so the server can emit partial transcripts while the caller is still speaking.
  • Finish with a text message end — the server finalises the session and returns the last final event.
  • For barge-in / interruption, treat an incoming partial/final event as the caller taking the floor and cancel any in-flight TTS stream. See LLM → TTS pipeline.

Source: Shunyalabs ASR Gateway API Reference (31 March), WebSocket Streaming API → "Audio Formats"; Shunyalabs TTS Developer Documentation v1.0 (March 2026), §8.2 Telephony Formats. Codec descriptions reproduced verbatim.
