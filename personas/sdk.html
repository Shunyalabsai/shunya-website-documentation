Step 1: Mint a Bearer token

Exchange your API key once at POST https://app.shunyalabs.ai/api/auth/token. Keep the API key on the server side; never send it to end-user clients.

curl -X POST 'https://app.shunyalabs.ai/api/auth/token' \
  -H 'api-key: YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"expires_in": 86400}'

Step 2: Standard TTS with requests

import requests

r = requests.post(
    "https://ttsv2.shunyalabs.ai/v1/omni-voice/synthesize",
    headers={"Authorization": f"Bearer {TOKEN}"},
    json={"text": "Hello, how are you today?", "voice": "Meera"},
    timeout=120,
)
r.raise_for_status()
open("hello.wav", "wb").write(r.content)

Step 3: OpenAI-compatible with the OpenAI SDK

If you already use openai.audio.speech.create(), keep your code and point base_url at Shunya. Pass the Bearer token as api_key. Raw PCM output is useful for streaming and voice-agent pipelines.

from openai import OpenAI

client = OpenAI(api_key=TOKEN, base_url="https://ttsv2.shunyalabs.ai/v1")

resp = client.audio.speech.create(
    model="tts-1",
    input="Hello, how are you today?",
    voice="Meera",
    response_format="pcm",
)
resp.stream_to_file("hello.pcm")

Step 4: Education TTS (LaTeX)

Add "latex": true when the input contains LaTeX expressions, and set "language" to identify the content language:

r = requests.post(
    "https://ttsv2.shunyalabs.ai/v1/omni-voice/synthesize",
    headers={"Authorization": f"Bearer {TOKEN}"},
    json={"text": "If $x^2 = 49$, what is the value of x?", "voice": "Meera", "latex": true, "language": "en"},
    timeout=120,
)

Step 5: LLM → TTS pipeline

For conversational voice agents, pipe LLM output into TTS at sentence boundaries. See the LLM → TTS pipeline for the pattern and the Pipecat example.

Step 6: Ship checklist

  • ✅ API key stored server side, never hardcoded
  • ✅ Bearer token minted from the backend and reused until near expiry
  • ✅ response_format matched to the use case (PCM for real-time)
  • ✅ Sentence-boundary buffering when piping from an LLM (don't flush per token)
  • ✅ Credentials kept out of browser code, mobile app bundles, public repositories, and logs
