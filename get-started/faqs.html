Getting Started & Account

Setting up your account, getting API keys, and troubleshooting first-use issues.

? How do I get an API key?

Visit shunyalabs.ai and sign up or log in. Complete the onboarding flow, which adds testing credits to your account, then generate an API key from your ShunyaLabs account.

The API key is not sent to the transcription or synthesis endpoints. Exchange it for a short-lived Bearer token via the Auth API and send that token on every request. Keep the API key on the server side; do not expose it in browser code, mobile app bundles, public repositories, or logs.

? I'm getting "401 Unauthorized" errors. What's wrong?

A 401 means the token is missing, invalid, or expired. The ASR guide returns 401 for a missing, invalid, or expired token. Mint a fresh token at POST /auth/token (ASR) or POST https://app.shunyalabs.ai/api/auth/token (TTS) and retry.

  • You are sending Authorization: Bearer <token>, not the raw API key
  • The token has not expired; cache and reuse it until shortly before expiry, then re-mint on expiry or a 401
  • There are no extra spaces or newlines in the header value

? What is the difference between a model and an endpoint?

A model is the underlying AI engine that performs the task, for example zero-indic for STT. Each model has specific capabilities and supported languages. An endpoint is the API URL through which you access the capability, such as /v1/audio/transcriptions for batch STT, /v1/omni-voice/synthesize for TTS, or /v1/audio/speech for the OpenAI-compatible TTS endpoint.

Multiple models can be accessed through the same endpoint by changing the model parameter. Similarly, the same model may be accessible through different endpoints (batch vs. streaming). The Capability matrix page provides a comparison of the available models and their characteristics.

Speech-to-Text (STT)

Issues with transcription accuracy, audio formats, streaming, and batch processing.

? Why is my transcript inaccurate?

Transcription accuracy depends on several factors. Here are the most common fixes:

  • Audio quality: Ensure the recording is clear, with minimal background noise. For streaming, send 16-bit signed PCM at 16 kHz (the default sample rate); 8 kHz is also supported.
  • Language selection: Set the correct language_code on batch requests (it defaults to auto). On streaming, language is required: there is no auto-detect, and omitting it or sending "auto" produces wrong output.
  • Model selection: Pick a model tuned for your audio: zero-indic for Indian languages, zero-universal for English and international content, zero-med for healthcare, zero-codeswitch for Hinglish/Tanglish.

See the ASR overview for the full set of request fields.

? What audio formats are supported for STT?

Batch transcription (POST /v1/audio/transcriptions) accepts WAV, MP3, FLAC, OGG, and Opus files up to 50 MB. Supply the audio as a file upload, as base64 (audio_base64), or via a url; exactly one of the three is required.

For streaming (WS /v1/realtime), send raw 16-bit signed PCM, little-endian, mono at the declared sample rate (default 16000; 8000 is supported).

? How do I transcribe a long audio file?

Use the batch endpoint (POST /v1/audio/transcriptions) for pre-recorded files. The batch endpoint accepts files up to 50 MB and returns the transcript in a single response.

If your file is larger than 50 MB, split the audio into segments and process them in parallel. See the ASR overview for details.

? Why is streaming STT not working?

Streaming STT uses a WebSocket connection. Common issues include:

  • Wrong endpoint: Use wss://asrv2prod.shunyalabs.ai/v1/realtime (wss://asrv2prod.shunyalabs.ai/ws behaves the same), not the HTTP URL
  • Auth: Send the short-lived access token (from POST /auth/token) as the token field of your first message, as a ?token= query parameter, or as Authorization: Bearer on the upgrade; not the raw API key
  • Missing language: language is required in the init message. There is no auto-detect on streaming; omitting it or sending "auto" gives wrong output
  • Audio format mismatch: Send 16-bit signed PCM, little-endian, mono, at the sample rate you declared (default 16000). Check your microphone and encoder settings
  • Connection closed early: Pace your frames roughly in real time (20-320 ms per frame) and finish by sending the text message end

Refer to the Streaming guide for code examples in Python and Node.js.

? How do I improve accuracy for domain-specific terms?

Choose the model that matches your domain. zero-med automatically corrects medical terminology, and zero-codeswitch restores English tokens in Hinglish and Tanglish audio. The model field is optional and defaults to your account's model.

For healthcare vocabulary specifically, zero-med is the model to use. See the models page for guidance on picking the right one.

? What is the difference between the Zero models?

Shunya Labs offers four STT model families, selected via the model parameter:

  • zero-indic: tuned for Indian languages, handling regional accents and code-switching.
  • zero-universal: English and international content; the strongest on English.
  • zero-med: English and Indic, with automatic medical-terminology correction.
  • zero-codeswitch: Hinglish, Tanglish, and similar mixed speech, restoring English tokens to Latin script.

The model field is optional; when omitted, the account's default model is used. See the models page for details.

? How do I enable diarization (speaker labels)?

Diarization labels each segment of the transcript with the speaker. Set the diarize field to true, and optionally pass num_speakers as a hint for the expected number of speakers:

curl -X POST https://asrv2prod.shunyalabs.ai/v1/audio/transcriptions \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -F "file=@meeting.wav" \
  -F "model=zero-indic" \
  -F "diarize=true" \
  -F "num_speakers=3" \
  -F "response_format=verbose_json"

With response_format=verbose_json, the response includes a speakers array, speaker_turns, and a speaker field on each segment. On streaming, set diarize/num_speakers in the init message and read speaker from final events (it may be null on very short segments).

? Why is punctuation and capitalization missing in my transcript?

The STT API returns the raw transcript text. There is no punctuation parameter; add punctuation and capitalization as a formatting step in your application.

Set response_format=verbose_json to get segments and word-level timing to work with.

? How do I get word-level timestamps?

Word-level timestamps come with the verbose response format. Set response_format=verbose_json on your batch request:

curl -X POST https://asrv2prod.shunyalabs.ai/v1/audio/transcriptions \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -F "file=@speech.wav" \
  -F "model=zero-indic" \
  -F "response_format=verbose_json"

The response includes a words array, each entry with word, start, and end (in seconds), plus segments with segment-level start/end. Word timestamps are useful for subtitle generation and audio alignment.

? Why is language auto-detection not working correctly?

Auto-detection only applies to batch requests, where language_code defaults to auto. If the detection is off, set language_code explicitly to the correct language code.

For streaming, there is no auto-detection: language is required in the init message, and omitting it or sending "auto" gives wrong output.

? How do I transcribe audio with multiple speakers?

Enable diarization with the diarize field, and optionally pass num_speakers as a hint. For batch:

curl -X POST https://asrv2prod.shunyalabs.ai/v1/audio/transcriptions \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -F "file=@meeting.wav" \
  -F "model=zero-indic" \
  -F "diarize=true" \
  -F "num_speakers=4" \
  -F "response_format=verbose_json"

The response's speakers array lists the detected speakers, each segment carries a speaker, and speaker_turns gives the chronological turns. Use a good-quality microphone and minimize overlapping speech for the best results.

? How does the API handle silence and non-speech audio?

There are no VAD (voice-activity-detection) parameters in the API. The transcription engine handles silence in the audio automatically.

For streaming, just send raw PCM frames as audio arrives, paced roughly in real time, and finish with the text message end. See the Streaming guide for the full protocol.

? Can I get a translation of my transcript?

Transcription itself does not return a translation. To translate the resulting transcript between Indian languages, use Vāķ Translate, which covers 2,970 language pairs.

For intent, summary, and sentiment on a transcript, use the Speech Intelligence endpoint (POST /v1/speechintelligence).

? Does the API return confidence scores?

No. The transcription response returns the text and, with response_format=verbose_json, segments, words, speakers, and timing metadata, but no per-segment confidence score.

? My audio file is too large. What are the limits?

Batch STT accepts audio files up to 50 MB. Files larger than that return a 413 error. If your file exceeds the limit, split it into smaller segments before uploading.

To split large audio files, use tools like ffmpeg:

ffmpeg -i large_audio.wav -f segment -segment_time 600 -c copy chunk_%03d.wav

This command splits the audio into 10-minute chunks. You can then process the chunks in parallel using multiple API requests.

? How do I transcribe streaming audio from a microphone?

Open a WebSocket to wss://asrv2prod.shunyalabs.ai/v1/realtime, send an init message with your access token and language, then stream raw PCM audio captured from the microphone:

import asyncio, websockets, pyaudio

async def stream_microphone():
    async with websockets.connect("wss://asrv2prod.shunyalabs.ai/v1/realtime") as ws:
        await ws.send('{"token": "<access_token>", "language": "hi", "sample_rate": 16000}')
        p = pyaudio.PyAudio()
        stream = p.open(format=pyaudio.paInt16, channels=1, rate=16000, input=True)
        while True:
            data = stream.read(4096)
            await ws.send(data)

asyncio.run(stream_microphone())

You'll receive ready, partial, and final events. See the Streaming guide for complete Python and Node.js examples.

? What is the difference between real-time and batch transcription?

Streaming (WS /v1/realtime) processes audio as it is captured over a WebSocket, emitting partial (interim) and final (stable) segments as speech happens. It is for live audio.

Batch (POST /v1/audio/transcriptions) sends a complete pre-recorded file and returns the full transcript in one response. Both transport modes share the same models and use the same short-lived access token.

? How do I handle multiple languages in a single audio file?

For a batch request, leave language_code unset (it defaults to auto) so the engine handles the language automatically:

curl -X POST https://asrv2prod.shunyalabs.ai/v1/audio/transcriptions \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -F "file=@multilingual_speech.wav" \
  -F "model=zero-universal"

For streaming, language is required and there is no auto-detect, so pick the dominant language for the session.

? How do I transcribe audio in real time for live captions?

Connect to wss://asrv2prod.shunyalabs.ai/v1/realtime and send an init message with your access token and a required language. Then stream raw PCM frames paced roughly in real time.

Display partial events as interim captions, then replace them with final events as they arrive. The full transcript is the concatenation of final.text in seg order. Finish with the text message end.

? Can I use Shunya STT for call center analytics?

Yes. The batch endpoint can process recorded calls, and the streaming endpoint can transcribe live calls. Enable diarization (diarize, plus num_speakers as a hint) to distinguish agent from customer.

For telephony audio at 8 kHz, send PCM at sample_rate: 8000 on streaming, or upload an 8 kHz WAV/MP3/etc. file to batch. Run the resulting transcript through Speech Intelligence (POST /v1/speechintelligence) for intent, summary, and sentiment.

Text-to-Speech (TTS)

Authentication, the omni-voice synthesize endpoint (standard and education), the OpenAI-compatible endpoint, and Pipecat.

? How does TTS authentication work?

Exchange your API key once for a short-lived Bearer token at POST https://app.shunyalabs.ai/api/auth/token. Send the API key in the api-key header and a token lifetime in seconds in the body, for example {"expires_in": 86400}. Use the returned token as Authorization: Bearer <token> on every TTS call.

curl -X POST 'https://app.shunyalabs.ai/api/auth/token' \
  -H 'api-key: YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"expires_in": 86400}'

Keep API keys and auth tokens on the server side. Do not expose them in browser code, mobile app bundles, public repositories, or logs. Store the API key in a backend or secret manager, mint the token from the backend, reuse it until near expiry, then refresh.

? How do I synthesize speech from text?

Call POST https://ttsv2.shunyalabs.ai/v1/omni-voice/synthesize with the text and the requested voice:

curl -X POST 'https://ttsv2.shunyalabs.ai/v1/omni-voice/synthesize' \
  -H "Authorization: Bearer $YOUR_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"text": "If Modi is prime minister who is Amit Shah?", "voice": "Meera"}' \
  --output hello.wav

The key fields are text (content to synthesize) and voice (the requested ShunyaLabs voice).

? How do I synthesize LaTeX (education) content?

Use the same omni-voice/synthesize endpoint with "latex": true when the input contains LaTeX expressions, and set language to identify the content language:

curl -X POST 'https://ttsv2.shunyalabs.ai/v1/omni-voice/synthesize' \
  -H "Authorization: Bearer $YOUR_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"text": "If $x^2 = 49$, what is the value of x?", "voice": "Meera", "latex": true, "language": "en"}' \
  --output answer.wav
? How do I use the OpenAI-compatible endpoint?

Use POST https://ttsv2.shunyalabs.ai/v1/audio/speech with the OpenAI request shape:

curl -X POST 'https://ttsv2.shunyalabs.ai/v1/audio/speech' \
  -H "Authorization: Bearer $YOUR_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"model": "tts-1", "input": "Hello, how are you today?", "voice": "Meera", "response_format": "pcm"}' \
  --output speech.pcm

Raw PCM output is useful for streaming and voice-agent pipelines. Select the response format required by your integration as supported by the API.

? How do I use TTS with Pipecat?

Configure the Pipecat TTS service with the ShunyaLabs token and base URL, and use an OpenAI-compatible voice name such as nova:

from pipecat.services.openai import OpenAITTSService

tts = OpenAITTSService(
    api_key="YOUR_TOKEN",
    base_url="https://ttsv2.shunyalabs.ai/v1",
    voice="nova",
)

api_key is Pipecat's field name; pass the ShunyaLabs auth token as its value.

The guide's examples use the voice Meera for the standard and OpenAI-compatible endpoints, and nova for Pipecat. Confirm the voices and languages you require with ShunyaLabs before production rollout.

Select the response format required by your integration, as supported by the API. The guide names raw PCM (response_format="pcm") as useful for streaming and voice-agent pipelines.

Latency is intentionally not hard-coded in the integration guide because it may vary by product version or client plan. The integration guide does not hard-code a text length limit; limits may vary by product version or client plan. Use the latest API documentation at ttsv2.shunyalabs.ai/docs for supported request fields.

API & Integration

Authentication, error codes, rate limits, and WebSocket connections.

? What are the API rate limits?

Both guides document a 429 (rate limit) error. The TTS guide intentionally does not hard-code rate or concurrency limits because they may vary by product version or client plan; confirm your required traffic with ShunyaLabs before production rollout.

For batch STT, the documented limit is the 50 MB file size; files larger than that return 413. See the Rate limits page for what is documented.

? Why am I getting "429 Too Many Requests"?

The 429 status code means you have exceeded the rate limit. Both the ASR and TTS guides list 429 in their error tables.

  • Wait and retry with exponential backoff
  • Reduce concurrency: throttle parallel requests
  • Confirm your plan: rate limits may vary by product version or client plan
? How do I call TTS from Python?

Mint a short-lived Bearer token with Python requests, then call the omni-voice synthesize endpoint:

import requests

# 1. Mint a Bearer token
token = requests.post(
    "https://app.shunyalabs.ai/api/auth/token",
    headers={"api-key": "YOUR_API_KEY"},
    json={"expires_in": 86400},
).json()["token"]

# 2. Synthesize with the token
r = requests.post(
    "https://ttsv2.shunyalabs.ai/v1/omni-voice/synthesize",
    headers={"Authorization": f"Bearer {token}"},
    json={"text": "Hello, how are you today?", "voice": "Meera"},
)
r.raise_for_status()
with open("hello.wav", "wb") as f:
    f.write(r.content)

For the OpenAI-compatible endpoint, point the OpenAI SDK at https://ttsv2.shunyalabs.ai/v1. See the Python integration guide for full examples.

? Can I use the OpenAI SDK with Shunya?

Yes, the TTS endpoint is OpenAI-compatible. Point the OpenAI SDK's base_url to the TTS base URL and use your Bearer token:

from openai import OpenAI

client = OpenAI(
    api_key="YOUR_TOKEN",
    base_url="https://ttsv2.shunyalabs.ai/v1",
)
resp = client.audio.speech.create(
    model="tts-1",
    input="Hello, how are you today?",
    voice="Meera",
    response_format="pcm",
)
resp.stream_to_file("hello.pcm")

Standard parameters like model, input, voice, and response_format work as documented in the guide. See the OpenAI compatibility guide.

? How do I handle WebSocket reconnections?

Implement reconnection logic with exponential backoff for production WebSocket clients:

  • Listen for the close event and attempt to reconnect
  • Start with a short delay and double it up to a maximum
  • Add jitter to avoid thundering herd on reconnection
  • On reconnect, re-send the streaming init message with your access token and language

The ASR realtime WebSocket endpoint (wss://asrv2prod.shunyalabs.ai/v1/realtime) supports reconnection; re-establish the connection and resume streaming audio. Transcript already received via final events stays valid.

? What are the common HTTP status codes and what do they mean?

The ASR guide documents these error status codes for its endpoints:

  • 400 - Bad request (missing/invalid input, or audio exceeds your plan limit)
  • 401 - Missing, invalid, or expired token; re-mint at /auth/token
  • 402 - Insufficient balance (at /auth/token)
  • 403 - Token not authorized for this endpoint
  • 413 - Upload too large (limit 50 MB)
  • 415 - Unsupported audio format
  • 429 - Rate limit exceeded
  • 504 - Request timed out

See the Error codes reference for complete details.

? What are the API timeout settings?

The integration guides do not hard-code timeout values. The ASR guide documents a 504 (request timed out) error for the batch endpoint. Configure your HTTP client with sensible timeout values for your use case.

? How do I implement retry logic?

Implement retry logic with exponential backoff in your HTTP client. Only retry on 429 (rate limited) and 5xx (server error) status codes. For ASR, re-mint the access token on expiry or a 401.

import time
import random

def retry_with_backoff(fn, max_retries=5, base_delay=1.0):
    for attempt in range(max_retries):
        try:
            return fn()
        except Exception as e:
            if attempt == max_retries - 1:
                raise
            delay = base_delay * (2 ** attempt) + random.uniform(0, 0.5)
            time.sleep(delay)
? Why is my WebSocket handshake failing?

WebSocket handshake failures are usually caused by:

  • Incorrect URL scheme: Use wss://asrv2prod.shunyalabs.ai/v1/realtime for secure connections
  • Missing authentication: Include the short-lived access token (from POST /auth/token) as the token field of your first message, the ?token= query parameter, or Authorization: Bearer on the upgrade
  • Firewall blocking: Ensure WebSocket connections on port 443 are allowed

Refer to the Streaming guide for WebSocket connection examples.

? Is the batch API synchronous or asynchronous?

Batch transcription (POST /v1/audio/transcriptions) is synchronous: it uploads a pre-recorded file and returns the full transcript in a single response. There is no job queue or webhook.

Streaming (WS /v1/realtime) is a live WebSocket session that emits partial and final events as audio arrives. TTS endpoints (omni-voice/synthesize and audio/speech) are synchronous HTTP calls that return the audio bytes.

? How do I debug API errors?

Start by checking the HTTP status code and response body. Most errors return a status code and a message describing the problem, for example 400 for a malformed request or 401 for an invalid token.

Log request URLs, headers, and response status codes in your client, and redact credentials before storing logs. The batch transcription response includes a request_id field (visible with response_format=verbose_json); quote it when contacting support.

? How do I enable logging for API calls?

Log the request URL, status code, and response body from your HTTP client. Keep API keys and auth tokens out of logs; store them on the server side in a secret manager.

The integration guides state that API keys and authentication tokens must not be exposed in logs.

? How do I set up CORS for web applications?

The integration guides do not document CORS configuration. For web applications, keep API keys and tokens on the server side and route API calls through a backend proxy; do not expose them in browser code.

? How do I set up webhooks for job completion?

No webhook is needed. Batch transcription (POST /v1/audio/transcriptions) is synchronous and returns the full transcript in a single response:

curl -X POST https://asrv2prod.shunyalabs.ai/v1/audio/transcriptions \

For TTS, mint a Bearer token, then call the omni-voice synthesize endpoint:

# 1. Mint a Bearer token
curl -X POST 'https://app.shunyalabs.ai/api/auth/token' \
  -H 'api-key: YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"expires_in": 86400}'

# 2. Synthesize with the token
curl -X POST 'https://ttsv2.shunyalabs.ai/v1/omni-voice/synthesize' \
  -H "Authorization: Bearer $YOUR_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"text": "Hello world", "voice": "Meera"}' \
  --output hello.wav

All API endpoints are documented in the API Reference.

? How do I rotate API keys without downtime?

Create a new API key in the dashboard while keeping your existing key active. Update your application to use the new key, test in staging, then update production.

After confirming production is stable with the new key, revoke the old key. The Compliance page recommends rotating on a quarterly schedule or immediately on suspected compromise, and notes that revocation takes effect in under 60 seconds.

? How do I set custom headers in API requests?

The integration guides do not document custom request headers. The batch transcription response includes a request_id field in the body (visible with response_format=verbose_json); quote it when contacting support.

? How do I migrate from another speech API provider?

Since Shunya is OpenAI-compatible for TTS, you only need to change the base_url and api_key in existing OpenAI integration code. For other providers, update your code to use Shunya's API format.

The OpenAI compatibility guide provides a side-by-side comparison if migrating from OpenAI Speech Services.

Deployment & On-Prem

Self-hosting, hardware requirements, air-gapped environments, and data security.

? Can I deploy Shunya on my own hardware?

Yes. Shunya Labs supports on-prem / VPC deployment for organizations that need data residency, low latency, or air-gapped operation. You deploy the same Triton containers that power the cloud inside your network, with REST and WebSocket edge services exposing the same API contract.

See the Deployment guide for the two deployment shapes and contact Shunya Labs for a deployment evaluation.

? What are the hardware requirements?

Shunya does not publish a sizing matrix. Hardware requirements depend on concurrency, codec, audio length, NLP add-ons, and Triton configuration.

Contact Shunya Labs for a sizing exercise before specifying hardware.

? How does air-gapped deployment work?

For environments with no internet connectivity, pull the open model weights once on an internet-connected machine, then transfer them across:

  1. Run huggingface-cli download for the models you need on a connected workstation
  2. Package the models directory as a signed tarball
  3. Verify checksums and transfer via signed media to the secure zone
  4. Load the model from the local path; no further network calls are needed

For production-quality serving in an air-gapped zone (multi-tenant, streaming, horizontally scaled), the on-prem package is easier than rolling your own Triton configuration. See the Deployment guide or contact Shunya Labs.

? Is my data encrypted?

Yes. Shunya Labs follows industry-standard security practices:

  • In transit: TLS 1.3 for all API and WebSocket connections
  • At rest: AES-256-GCM with envelope encryption
  • Audio: encrypted during processing and deleted on transcription completion; transcripts are not retained in the default configuration

Shunya is SOC 2 Type II, ISO/IEC 27001:2022, HIPAA, GDPR, and CCPA aligned. See the Compliance page for details.

? How do I deploy using Docker or Kubernetes?

The on-prem package ships as Triton Inference Server containers with a REST and WebSocket edge service and a management plane for API keys, quotas, and monitoring. It includes Helm charts (Kubernetes) or docker-compose for smaller setups.

Contact Shunya Labs to obtain the deployment package. See the Deployment guide for details.

? How do I update models in an on-prem deployment?

The on-prem package includes an update channel whose cadence you control. Updates are delivered by Shunya Labs; contact support or your account manager for the update procedure.

? How do I monitor or scale an on-prem deployment?

The on-prem package includes a management plane for API keys, quotas, and monitoring. Sizing and scaling guidance depends on your expected traffic and concurrency, which Shunya does not publish as a fixed matrix.

Contact Shunya Labs for a sizing exercise and scaling recommendations.

Additional & questions

Latency, data residency, security, and vocabulary topics.

? What is the latency for real-time transcription?

During a streaming session the ASR endpoint emits partial events roughly every 640 ms with the in-progress text for the current segment. Latency depends on network, audio, and model and is not hard-coded in the guides.

Pace audio roughly in real time and reconnect on unexpected close to keep the session healthy. Confirm the latency you require before production rollout.

? How do I find my data residency and region information?

The cloud API default region is Asia (Mumbai). Enterprise customers can request US or EU endpoints.

For on-prem / VPC deployments, data residency is entirely under your control since the inference servers run within your infrastructure. See the Deployment guide.

? How do I enable audit logging for my account?

Audit logging is a documented control on the management plane: audit logging on every privileged action with logs shipped to an immutable store, and role-based access control with least-privilege defaults.

See the Compliance page for the documented security and access controls.

? How do I use custom vocabulary with STT?

There is no custom-vocabulary parameter in the STT API. Accuracy for domain-specific terms comes from choosing the right model: zero-med automatically corrects medical terminology, and zero-codeswitch restores English tokens in code-switched speech.

curl -X POST https://asrv2prod.shunyalabs.ai/v1/audio/transcriptions \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -F "file=@lecture.wav" \
  -F "model=zero-med" \
  -F "language_code=en"

See the models page for guidance on picking the model that matches your domain.

? How do I transcribe audio with background noise?

There is no VAD parameter in the API; the transcription engine handles silence and non-speech audio automatically. For the best results, record clean audio with minimal background noise, and consider preprocessing with a noise-reduction tool like ffmpeg or sox before submission.

? How do I customize the voice for my brand?

Request the voice you want in the voice field of the synthesize request. Voice and language support is confirmed per client plan. Before production rollout, confirm the voices and languages you require with ShunyaLabs.
