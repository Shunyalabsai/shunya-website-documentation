Voice Agent - Meera

Meera is a ready-to-configure outbound calling agent framework from Shunya. Think of it as a programmable call executive: you define what Meera should say, how she should speak, when she should retry, and where call outcomes should be delivered.

In one line: what Meera does
Meera helps you automate outbound conversations like lead qualification, payment reminders, appointment reminders, post-service feedback, and campaign follow-ups without manually calling each customer.

What Meera actually is

Meera is not just text-to-speech. It is a complete call workflow layer that combines:

  • agent behavior configuration (prompt, tone, guardrails)
  • telephony routing (caller ID and account readiness)
  • call orchestration (queueing, retries, timing windows)
  • event delivery (webhooks for outcomes, summary, and transcript events)

When teams use Meera

Sales follow-up

Call fresh leads in minutes, pre-qualify intent, and send structured outcomes to your CRM.

Operations reminders

Automate appointment, billing, and renewal reminders with retry logic and language control.

Support outreach

Run post-resolution feedback calls and capture outcomes such as interested, callback_requested, or no_answer.

Request format (Content-Type) made simple

All write requests in Meera are JSON payloads. That is why headers include Content-Type: application/json. In practice:

  • Who you are: Authorization: Bearer YOUR_API_KEY (your console API key, sent directly; see Authentication)
  • What you are sending: Content-Type: application/json
  • What Meera reads: your JSON fields like prompt, voice, messages, phone, and callback_url
Base URL
https://agents.shunyalabs.ai for production API calls.

Authentication

Meera uses your Shunya console API key directly. Send it on every request as Authorization: Bearer YOUR_API_KEY. Once authenticated, the same key is used for all agent, telephony, and call endpoints.

  1. Sign in at accounts.shunyalabs.ai.
  2. Go to API Keys and click Create New Key.
  3. Copy the key immediately. It is shown only once.
  4. Store it in a .env file or secrets manager; never commit it to source control.

Set the environment variable

export SHUNYALABS_API_KEY="sk-your-key-here"
$env:SHUNYALABS_API_KEY = "sk-your-key-here"

Then reference it in curl examples:

curl -s -H "Authorization: Bearer $SHUNYALABS_API_KEY" \
  "https://agents.shunyalabs.ai/api/health"

Start here in 5 minutes

  1. Get your API key from the console and set SHUNYALABS_API_KEY (see Authentication).
  2. Validate connectivity with GET /api/health.
  3. Create an agent with a system prompt and opening message.
  4. If you bring your own telephony account, register a caller ID first.
  5. Trigger a call with POST /api/v1/calls.
  6. Capture outcome data via configured webhook endpoint.

Step 1: Create your Meera agent

Minimum required fields are name, prompt.system_prompt, and messages.opening. Start simple, then add behavior and outcomes as your use case matures.

curl -s -X POST "https://agents.shunyalabs.ai/api/v1/agents" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Meera Sales Assistant",
    "pipeline_type": "shunya",
    "prompt": {
      "system_prompt": "You are a concise, polite outbound sales assistant."
    },
    "voice": {
      "language": "hi",
      "tone": "professional",
      "accent": "indian",
      "gender": "female",
      "tts_speed": 1.0
    },
    "messages": {
      "opening": "Namaste! Main Meera bol rahi hoon. Kya aapke paas 2 minute hain?"
    }
  }'
Important
For pipeline_type: "shunya", do not pass internal provider IDs or tts_voice_id. Keep configuration at behavior-level inputs only.

Step 2: Telephony readiness

If you use your own telephony account, register your account and caller ID first. If Shunya provisions telephony for your org, you can skip to the next step.

Get Plivo Auth ID and Auth Token (BYO telephony)

When you bring your own Plivo account, Meera needs your Plivo credentials to place outbound calls from your number. These are separate from your Shunya API key.

  1. Sign in to the Plivo Console.
  2. On the dashboard, copy your Auth ID. This is auth_id in the registration payload.
  3. Reveal and copy your Auth Token. This is auth_token. You can regenerate it from the console if needed.
  4. Confirm the phone number you pass as phone_number is already provisioned in that Plivo account.
Keep Plivo credentials server-side
Store auth_id and auth_token in your backend or secrets manager only. Never expose them in frontend code or commit them to git. 
curl -s -X POST "https://agents.shunyalabs.ai/api/telephony/numbers" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "tag": "new",
    "provider": "plivo",
    "auth_id": "YOUR_PLIVO_AUTH_ID",
    "auth_token": "YOUR_PLIVO_AUTH_TOKEN",
    "phone_number": "+918031137171",
    "label": "Outbound caller ID"
  }'

Step 3: Trigger outbound calls

Calls are queued immediately and processed asynchronously. Use a unique external_id per call to avoid accidental duplicates.

curl -s -X POST "https://agents.shunyalabs.ai/api/v1/calls" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "agent_id": "YOUR_AGENT_ID",
    "phone": "+919876543210",
    "from_number": "+918031137171",
    "callback_url": "https://your-server.example.com/webhooks/call-callback",
    "external_id": "lead-2026-08-26-001",
    "context": {
      "customer_name": "Rahul Sharma",
      "city": "Delhi"
    },
    "echo": {
      "campaign": "festive-offer",
      "source": "partner-api"
    },
    "start": 900,
    "end": 2100,
    "timezone": "Asia/Kolkata",
    "retries": 1
  }'

Step 4: Receive outcomes (no polling needed)

There is no call-status polling endpoint. Meera is webhook-first: once a call completes, your endpoint receives the event payload.

sequenceDiagram participant App as Your App participant API as Shunya Agents API participant Dialer as Dialing Engine participant Hook as Your Webhook App->>API: POST /api/v1/calls API-->>App: 201 {status: "queued", call_id} API->>Dialer: enqueue and dial Dialer-->>API: call completed event API->>Hook: webhook payload (outcome, transcript/summary if enabled)

Common integration patterns

BYO telephony

Register Plivo/Twilio first, then pass from_number in call requests. Best for teams with existing telephony control.

Shunya-managed telephony

Skip telephony registration and start from agent creation. Fastest path for pilot rollouts.

Common status codes

  • 200 success on read/update operations
  • 201 agent/call/telephony resource created
  • 204 delete/archive accepted
  • 401 missing or invalid API key
  • 409 duplicate external_id or telephony conflict
  • 422 invalid payload fields or structure
Callback signature note
callback_secret is accepted by the API, but callback signing may not be active in all environments. Validate payload shape and enforce source controls at your edge.
