API authentication

ASR authenticates with a short-lived access token minted from your API key; TTS authenticates with the API key directly.

Speech-to-Text (ASR)

You use your API key once to obtain a short-lived access token at POST /auth/token, then send that token on every ASR request. Do not send your API key to the transcription endpoints.

1. Mint a token:

curl --location --request POST 'https://asrv2prod.shunyalabs.ai/auth/token' \
  --header 'accept: application/json' \
  --header 'Authorization: Bearer <API_KEY_GENERATED_IN_DASHBOARD>'

Response 200 OK:

{ "token": "<access_token>", "expires_at": 1784745886, "expires_in": 900 }
FieldTypeDescription
tokenstringThe access token to use on ASR requests.
expires_atintegerUnix time when the token expires.
expires_inintegerSeconds until expiry (typically 900 = 15 min).

2. Use the token on every ASR request:

curl --location 'https://asrv2prod.shunyalabs.ai/v1/audio/transcriptions' \
  --header 'accept: application/json' \
  --header 'Authorization: Bearer <access_token>' \
  --form 'file=@"audio.wav"'
Token usage
The same access token authenticates batch (POST /v1/audio/transcriptions), realtime (WS /v1/realtime), Speech Intelligence (POST /v1/speechintelligence), and speaker enrolment. Cache and reuse it until shortly before expires_at; re-mint on expiry or a 401. Mint errors: 400 (no key supplied), 401 (invalid key), 402 (insufficient balance), 429 (too many requests).

Text-to-Speech (TTS)

TTS authenticates with a short-lived Bearer token minted from your API key at POST https://app.shunyalabs.ai/api/auth/token. Send the token on every TTS request; never send the API key to end-user clients.

1. Mint a Bearer token:

curl -X POST 'https://app.shunyalabs.ai/api/auth/token' \
  -H 'api-key: YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"expires_in": 86400}'

expires_in is the token lifetime in seconds; the example requests 24 hours. The response returns a token field to send as Authorization: Bearer YOUR_TOKEN on all TTS calls.

2. Use the token on every TTS request:

curl -X POST 'https://ttsv2.shunyalabs.ai/v1/omni-voice/synthesize' \
  -H "Authorization: Bearer $YOUR_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"text": "Hello, how are you today?", "voice": "Meera"}' \
  --output hello.wav
Keep credentials on the server side
Keep API keys and auth tokens on the server side. Do not expose them in browser code, mobile app bundles, public repositories, or logs. Store the API key in a backend or secret manager, mint the token from the backend, reuse it until near expiry, then refresh.
