Text-to-Speech (TTS)

ShunyaLabs TTS turns text into spoken audio. The recommended integration path covers standard omni-voice synthesis, education LaTeX TTS for math content, and an OpenAI-compatible voice-agent endpoint for Pipecat and similar frameworks. Every call authenticates with a short-lived Bearer token minted from your API key.

New endpoints
These endpoints are the recommended integration path for new client implementations and provide an improved experience over the previous TTS endpoints.

How authentication works

Generate an API key from your ShunyaLabs account, then exchange it for a short-lived Bearer token at POST /api/auth/token. Use the token as Authorization: Bearer YOUR_TOKEN on every TTS call. Request the token lifetime in seconds with expires_in (for example, 86400 for 24 hours), reuse it until it approaches expiry, then mint a fresh one. Keep the API key on the server side; never send it to end-user clients.

See Authentication for the full flow.

Standard TTS

Use the Omni Voice synthesis endpoint for standard text-to-speech generation. The body takes text (the content to synthesize) and voice (the requested ShunyaLabs voice).

curl -X POST 'https://ttsv2.shunyalabs.ai/v1/omni-voice/synthesize' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "text": "If Modi is prime minister who is Amit Shah?",
    "voice": "Meera"
  }' \
  --output speech.wav

Education TTS with LaTeX

For educational content containing mathematical expressions, enable LaTeX processing and provide the content language. Math-oriented content is handled through the same Omni Voice synthesis endpoint.

curl -X POST 'https://ttsv2.shunyalabs.ai/v1/omni-voice/synthesize' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "text": "If $x^2 = 49$, what is the value of x?",
    "voice": "Meera",
    "latex": true,
    "language": "en"
  }' \
  --output math.wav

Set latex to true when the input contains LaTeX expressions, and use language to identify the content language.

Voice Agent / OpenAI-compatible

For real-time voice-agent frameworks and integrations expecting an OpenAI-compatible speech interface, use the /v1/audio/speech endpoint. Requesting raw PCM output is useful for streaming and voice-agent pipelines.

curl -X POST 'https://ttsv2.shunyalabs.ai/v1/audio/speech' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "tts-1",
    "input": "Hello, how are you today?",
    "voice": "Meera",
    "response_format": "pcm"
  }' \
  --output speech.pcm

Pipecat

from pipecat.services.openai import OpenAITTSService

tts = OpenAITTSService(
    api_key="YOUR_TOKEN",
    base_url="https://ttsv2.shunyalabs.ai/v1",
    voice="nova",
)
Pipecat note
The api_key field name comes from Pipecat's OpenAI-compatible service interface; pass the ShunyaLabs auth token as its value. For Pipecat, use an OpenAI-compatible voice name such as nova in the client configuration.

Before production rollout

The examples above are sufficient for initial testing. Before moving a client workload to production, confirm the requirements relevant to that implementation: expected traffic, required voices and languages, output or streaming format, latency expectations, and credit or commercial plan. Supported voices, response formats, and rate or concurrency limits are intentionally not hard-coded because they may vary by product version or client plan.
