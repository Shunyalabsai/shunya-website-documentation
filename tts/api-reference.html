TTS API reference

Every endpoint in the ShunyaLabs Text-to-Speech API: authentication, standard omni-voice synthesis, education LaTeX TTS, and the OpenAI-compatible voice-agent endpoint, with request fields and examples.

New endpoints
These endpoints are the recommended integration path for new client implementations and provide an improved experience over the previous TTS endpoints.
Base URLs
Authentication: https://app.shunyalabs.ai
TTS: https://ttsv2.shunyalabs.ai

1. Authentication: POST /api/auth/token

ShunyaLabs TTS APIs use a short-lived Bearer token. Generate your API key from your ShunyaLabs account, then exchange it for a token using the authentication endpoint. Use the returned token as Authorization: Bearer YOUR_TOKEN on every TTS request.

Example (cURL):

curl -X POST 'https://app.shunyalabs.ai/api/auth/token' \
  -H 'api-key: YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"expires_in": 86400}'

expires_in specifies the requested token lifetime in seconds. In the example above, the token is requested for 86,400 seconds (24 hours). Use the token returned by this API as Authorization: Bearer YOUR_TOKEN in subsequent requests.

Recommended flow

  • Store the API key securely in your backend or secret manager.
  • Request an auth token from your backend when required.
  • Reuse the token until it approaches expiry, then obtain a fresh token.
  • Never send your ShunyaLabs API key directly to end-user clients.
Security
Keep API keys and authentication tokens on the server side. Do not expose them in browser code, mobile app bundles, public repositories, or logs.

2. Standard TTS: POST /v1/omni-voice/synthesize

Use the Omni Voice synthesis endpoint for standard text-to-speech generation.

Example (cURL):

curl -X POST 'https://ttsv2.shunyalabs.ai/v1/omni-voice/synthesize' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "text": "If Modi is prime minister who is Amit Shah?",
    "voice": "Meera"
  }' \
  --output speech.wav
FieldTypeDescription
textstringThe content to synthesize.
voicestringThe requested ShunyaLabs voice (for example, Meera).

3. Education TTS with LaTeX

For educational content containing mathematical expressions, enable LaTeX processing and provide the language. Math-oriented content is handled through the same Omni Voice synthesis endpoint.

Example (cURL):

curl -X POST 'https://ttsv2.shunyalabs.ai/v1/omni-voice/synthesize' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "text": "If $x^2 = 49$, what is the value of x?",
    "voice": "Meera",
    "latex": true,
    "language": "en"
  }' \
  --output math.wav
FieldTypeDescription
textstringThe content to synthesize, including any LaTeX expressions.
voicestringThe requested ShunyaLabs voice (for example, Meera).
latexbooleanSet to true when the input contains LaTeX expressions.
languagestringIdentifies the content language (for example, en).

4. Voice Agent / OpenAI-compatible: POST /v1/audio/speech

For real-time voice-agent frameworks and integrations expecting an OpenAI-compatible speech interface, use the /v1/audio/speech endpoint.

Example (cURL):

curl -X POST 'https://ttsv2.shunyalabs.ai/v1/audio/speech' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "tts-1",
    "input": "Hello, how are you today?",
    "voice": "Meera",
    "response_format": "pcm"
  }' \
  --output speech.pcm
FieldTypeDescription
modelstringThe model name (tts-1).
inputstringThe text to synthesize.
voicestringThe requested voice (for example, Meera).
response_formatstringThe output format (pcm for streaming and voice-agent pipelines).

The example requests raw PCM output, which is useful for streaming and voice-agent pipelines. Select the response format required by your integration as supported by the API.

5. Pipecat example

from pipecat.services.openai import OpenAITTSService

tts = OpenAITTSService(
    api_key="YOUR_TOKEN",
    base_url="https://ttsv2.shunyalabs.ai/v1",
    voice="nova",
)
Pipecat note
The api_key field name comes from Pipecat's OpenAI-compatible service interface; pass the ShunyaLabs auth token as its value. For Pipecat, use an OpenAI-compatible voice name such as nova in the client configuration.

6. Client integration checklist

  • Create or log in to your ShunyaLabs account at shunyalabs.ai.
  • Complete onboarding and confirm that testing credits are available.
  • Generate an API key.
  • Exchange the API key for a Bearer token using the Auth API.
  • Integrate Standard TTS, Education TTS, or the OpenAI-compatible endpoint as required.
  • Store credentials securely and refresh tokens before expiry.
  • Use the latest API documentation for supported request fields and integration details.

7. API documentation

Interactive API documentation is available at https://ttsv2.shunyalabs.ai/docs.

Before production rollout

The integration examples above are sufficient for initial testing. Before moving a client workload to production, confirm the production requirements relevant to that implementation, including expected traffic, required voices and languages, output or streaming format, latency expectations, and credit or commercial plan.

Items worth confirming for each client: supported voices and languages, available response formats, rate or concurrency limits, production credit or billing plan, and the preferred support or escalation channel. These details are intentionally not hard-coded in this guide because they may vary by product version or client plan.
